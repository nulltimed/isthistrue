## 2. Lo que hace este pase: dos redes, ninguna necesita que intervengas

### La pista se da también cuando el agente duda un poco

Antes, la pista solo se pasaba con **confianza alta**. Ahora, con confianza **media** también
se abre el rango. Verificado:

```
moderación fija 2             → num_speakers=2
agente 2, confianza ALTA      → min_speakers=2, max=3
agente 2, confianza MEDIA     → min_speakers=2, max=3     ← lo nuevo
agente 2, confianza BAJA      → automático
agente 1 (monólogo) ALTA      → num_speakers=1            ← el monólogo sigue blindado
agente 1, confianza MEDIA     → automático                ← un «1» dudoso ya no blinda
```

El razonamiento es correcto: **un rango es inofensivo** (no fuerza nada, solo impide el
disparate de fundir todo en una voz), mientras que fijar un número exacto sí puede hacer daño y
por eso sigue exigiendo confianza alta.

### Y si aun así sale mal, se repite solo

La red de verdad: al terminar la separación, el sistema **mira el resultado**. Si hay dos o más
voces y la minoritaria se queda por debajo del **20 %** del tiempo, repite la separación
diciéndole el número exacto de voces. Probado con tu caso real:

```
post 5 real (91,9 / 8,1)        → REPITE con num_speakers=2   ✔
post 5 sin dato del agente      → REPITE con num_speakers=2   ✔
reparto sano (60 / 40)          → no repite                   ✔
MONÓLOGO (una sola voz)         → no repite                   ✔  ← no se parte nunca
moderación ya fijó el número    → no repite                   ✔  ← quien manda, manda
```

Los dos últimos casos son los que impiden que la red haga daño: **un monólogo no se parte
jamás**, y si alguien ya decidió cuántas voces hay, no se le discute.

**Cuesta CPU, no dinero**: una segunda separación son 10-25 minutos más en un vídeo de 23
minutos, y solo ocurre cuando la primera salió torcida.
